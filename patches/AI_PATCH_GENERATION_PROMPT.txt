Copy and paste this prompt to an AI assistant (Claude, ChatGPT, etc.) to generate new patches:

- Tech Stack: Python 3.11+, FastAPI, SQLAlchemy, pytest
- Architecture: Layered (routes → services → repositories → models)
- Domain Models: Users, Projects, Issues, Comments, Tags
- Test Coverage: Unit tests, integration tests, E2E tests

EXISTING PATCHES (must not conflict):
1. 01-require-project-description.patch

   - Breaks 8 tests (2 unit + 6 integration)

2. 02-require-long-issue-titles.patch
   - Requires issue titles minimum 20 characters
   - Breaks ~10 tests (5 unit + 5 integration)

3. 03-require-long-comments.patch
   - Requires comments 15-1000 characters
   - Breaks ~10 tests (8 unit + 2 integration)

1. Must break 5-15 tests (realistic demo scope)
2. Must be independent (no conflicts with existing patches)
3. Should simulate realistic development scenarios
4. Must be reversible (git apply / git apply -R)
5. Should modify application code only (not test files)

TARGET DOMAIN:
[SPECIFY ONE: Projects / Issues / Comments / Tags / Users / Assignments / Status Workflow]
OR: Suggest the best domain based on existing patches

CHANGE IDEA:
[DESCRIBE YOUR IDEA, or ask "Please suggest a realistic breaking change"]

1. **File Changes**: Show exact modifications needed for:
   - app/schemas/[domain].py (Pydantic validation)

2. **Patch File**: Generate the complete git diff patch file content

3. **Test Analysis**:
   - Which tests will break and why?
   - Estimated test failure count (unit + integration)

4. **Documentation**: Write the patch section for patches/README.md including:
   - Purpose and changes
   - Expected impact
   - List of failing tests

5. **Independence Verification**: Confirm no conflicts with existing patches
